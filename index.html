Joyería personalizada: del dato a la automatización

Trabajé con los datos de un año de una tienda de joyas grabadas en plata 925 y baño de oro 18K. Me hice tres preguntas: cómo ordenar a los clientes, qué números revisar cada semana y qué tareas repetitivas se podrían automatizar.

Autora Yosseline · Ing. de Sistemas, 6.º ciclo, UCV Periodo Base 600 clientes · 20 productos · 800 pedidos · 1 500 consultas Herramientas Python (pandas) · n8n · Google Sheets · WhatsApp Cloud API

La base es un conjunto de datos de práctica que simula la operación de una joyería. Las cifras sirven para mostrar el método; con datos reales cambian los números, pero el proceso es el mismo.

Qué revisaría cada semana

Propongo un tablero corto con cuatro indicadores que el equipo pueda revisar en diez minutos. Ventas y margen dicen si el negocio crece. Puntualidad de entrega (OTIF), error de grabado y conversión de consultas dicen dónde se pierde dinero.

Ordenar a los clientes

Hoy las consultas llegan por cinco canales y no hay una etapa común. Propongo un embudo único, igual para Instagram, WhatsApp, TikTok, web y tienda. Además, cada cliente recibe un segmento RFM (recencia, frecuencia y monto) que decide qué mensaje se le envía.

Etapas del embudo

Consulta→ Cotizado→ Texto confirmado→ Pagado→ En taller→ Enviado→ Entregado→ Postventa / fecha especial

Las dos etapas resaltadas no existen en la base actual y son las que más valor agregan. "Texto confirmado" evita errores de grabado. "Postventa" convierte la fecha especial del regalo en una nueva venta.

Automatizaciones con n8n

Tres flujos que armé en n8n

Elegí las tareas que hoy dependen de que alguien se acuerde. Cada flujo lee y escribe en Google Sheets, que puede ser el CRM inicial, y avisa por WhatsApp. Los tres están en formato JSON de n8n: se importan con Import from file y solo falta conectar las credenciales.

1 · Alerta diaria de pedidos en riesgo

08:00 diario→Leer pedidos→Calcular llegada estimada→Priorizar→WhatsApp a operaciones
Problema
Qué hacePara cada pedido en taller estima la llegada (producción + 3 días de envío). Marca prioridad ALTA si llegará después de la fecha especial del cliente.
IndicadorOTIF y pedidos que llegan después de la fecha especial

  


  

    
2 · Nuevo pedido: validar el grabado y confirmar con el cliente

    
Webhook del pedido→Validar texto→Fecha prometida realista→¿Válido?→Cliente confirma por WhatsApp→Registrar en CRM

    

      
Problema

      
Qué haceRevisa largo, caracteres grabables y fechas inexistentes (31.02). Pide al cliente confirmar el texto exacto. Reemplaza la promesa fija de 7 días por producción + envío.

      
IndicadorError de grabado y devoluciones

    

    
"12.03.2019"     → ok
"31.02.2020"     → fecha inexistente
"Mamá ♥"         → caracteres no grabables
"Siempre juntos" → ok

  


  

    
3 · Recompra por fecha especial

    
10:00 diario→Leer CRM→Fechas que se cumplen en 21 días→Mensaje personalizado→Marcar contacto

    

      
Problema

      
Qué haceCuando falta poco para que se cumpla un año de la fecha especial (cumpleaños, aniversario, nacimiento), escribe al cliente con tiempo suficiente para producir y entregar.

  Key User
  
Cómo apoyaría en la implementación del ERP

  
Un Key User es el puente entre el equipo que usa el sistema y el proveedor que lo implementa. Conoce el proceso, prueba cada función con casos reales y enseña a sus compañeros. Este análisis ya me dio esa base: sé cómo fluye un pedido, qué datos faltan (texto confirmado, fecha especial) y qué reglas debe cumplir el ERP. Este sería mi plan para los primeros 90 días.
